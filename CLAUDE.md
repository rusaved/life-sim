# CLAUDE.md — симулятор жизни с душой

## Что строим
Веб-игра: одна человеческая жизнь по реальной статистике мира или эпохи России, решения по годам, смерть, карточка жизни для соцсетей и душа, которая копит черты между жизнями. Дизайн первой версии — `docs/01-design.md`.

## Где что лежит
- `docs/01-design.md` — дизайн; `docs/05-milestones.md` — вехи и задачи; `docs/data-sources.md` — источники данных
- `progress.md` — журнал и «Состояние» (новая сессия начинает отсюда), `feature_list.json` — задачи вехи с `passes`, `QUESTIONS.md` — вопросы продюсеру с вариантом по умолчанию
- `content/` — все тексты, события, данные стран и эпох; `src/platform/` — слой площадки (null, vk; позже yandex, crazygames, telegram)
- `content/brand.json` — название и хэштег (только здесь); `content/life.json` — свои тексты движка и интерфейса; `content/event-tags.json` — что событие требует и даёт (семья, переезд, утрата); `content/vk.json` — номер приложения VK
- `src/core/` — чистая логика без DOM (рождение, смертность, жизнь, душа, сохранение); `src/ui/` — экраны и карточки; `src/app.ts` — состояние и переходы
- `scripts/` — `verify.mjs`, `build-pages.mjs`, `check-vk.mjs`, `validate-content.ts`, `sim-lives.ts` (бот жизней), `make-og.mjs`; `e2e/` — Playwright; `tests/` — unit
- `docs/evidence/<веха>/` — доказательства (отчёт бота, плейтест, кадры до 300 КБ); `.claude/agents/playtester.md` — плейтестер

## Как работать
- Каркас, `scripts/verify.mjs`, Pages, слой VK и приёмы тестов берём из публичного репозитория той же студии https://github.com/rusaved/anomaly-shop (клонировать во временную папку и переносить нужное, не ссылаться на его файлы). Его `CLAUDE.md` — образец разделов и правил, этот файл дополнять по нему.
- Одна задача за раз: сделал → тест → «Состояние» в `progress.md` → коммит → push в ветку.
- Итог вехи — в `main`, последней строкой «Состояния» — «Ждёт решения продюсера».

## Команды
| Команда | Что делает |
|---|---|
| `npm ci` | зависимости (в `.npmrc` — `legacy-peer-deps`, иначе npm 10 падает на vitest) |
| `npm run dev` / `dev:vk` | сайт / сборка VK на заглушке моста (`?mock=vk`) |
| `npm run verify:fast` | типы → unit → контент → бот 200 жизней; после каждой задачи, до 5 минут |
| `npm run verify` | всё: + `build:pages`, `check:vk`, e2e (итог вехи, один раз + один повтор) |
| `npm run build:pages` | ссылка продюсера: сайт в `dist-pages/`, VK в `dist-pages/vk/` |
| `npm run sim:lives -- --n 1000 --report` | бот жизней против данных, отчёт в `docs/evidence/LS1/sim-lives.md` |
| `node scripts/make-og.mjs` | картинка превью ссылки после смены названия |

Ссылки для проверки: `?fresh=1` — с чистого листа (срабатывает один раз), `?s=<seed>` — родиться тем же младенцем, `vk/?mock=vk` — сборка VK в обычной вкладке.

## Готово
Задача — `passes: true` только по зелёному выводу этой сессии. Веха — все задачи `passes`, полный `verify` (+ один повтор), плейтестер без «2», итог в `progress.md` по шаблону брифа, `git push origin HEAD:main`, Pages выложены, последней строкой «Состояния» — «Ждёт решения продюсера».

## Жёсткие правила
- Репозиторий публичный: никаких личных данных, ключей, путей с чужих компьютеров, рабочих названий и разборов чужих игр. Тексты, события, картинки — свои; данные — только открытые, с источником.
- Без внешних запросов, кроме своего хоста; без рекламы и покупок до решения продюсера.
- Force push, PR и правки других репозиториев нельзя.
- Всё по-русски: код с понятными именами, тексты игры — живые, без канцелярита.
- Числа и тексты — в `content/`; в коде — только склейка. Название игры — только в `content/brand.json` (`validate:content` следит).
- Сборка `vk/`: ни одного чужого адреса (`check:vk`), сохранение только через слой площадки.
- Шапка модуля `src/`: «Что», «Кто зовёт», «Держать». Ноль ошибок консоли (e2e следит).
- Лимит сессии: 6 часов или 3 сжатия контекста — «Состояние», коммит, push в ветку, строка «Остановка по лимиту сессии: продолжить новой сессией».
